# 📌 专利标记助手 V4.4.0

一款为专利代理人 / 审查员打造的桌面端 `.docx` 处理工具。围绕「撰写 → 自查 → 标注 → 生成」全链路，
把 **附图标记自动标注、文本清洗、标点检查、错别字 / 重复字词检查、权利要求书引用审查、说明书检查**
集成到一个 PyQt6 界面里。

专利正文是常驻**主舞台**，支持**结构化实时编辑**；图片与公式**内联显示**，检查结果在原文上**内联高亮**，
问题与正文一屏对照。底层始终只操作 `<w:t>` XML 文本节点，保证**格式安全**：公式、形状、图片、样式
在所有自动化操作后逐字节保留。

> - 1框 回写只改动你改过的字，上下标、制表符、软回车、超链接不再被抹平；修正按「第几处」只改那一处。

发行包位于 [Releases](https://github.com/vvangpc/mark123/releases) 页面，两种形式任选，功能完全一致。

### 🅰️ 安装版（推荐）`mark123-Setup-vX.Y.Z.exe` · 约 32 MB

- 双击运行 → 向导中**可自选安装目录** → 自动创建开始菜单 / 桌面快捷方式 → 控制面板一键卸载
- 勾选「文件关联」后，**右键任意 `.docx` 即可看到「用专利标记助手打开」**，点击后软件启动并自动导入

- 启动时需解压到 `%TEMP%`，首次启动略慢（5–15 秒，有启动图遮挡）

> 🔄 **内置在线更新**：每次启动自动从 GitHub Releases 检查新版本（HTTPS），发现新版弹窗提示；
> 点「立即更新」即自动下载、校验 SHA256 后拉起安装程序。也可在右下角「⚙ 设置 → 🔄 检查更新」手动触发。
> 更新源全程走 GitHub，无需自建服务器。

## 主界面结构

无顶部标题栏，最大化内容与操作面积。左侧是「看与改」的主舞台，右侧是「选模块 → 点功能」的导航与文件操作。

```
┌──────────────────────────────────────────────────────────────────────┐
│  ┌─────────────────────────────────────────┐  ┌──────┬─────────────┐  │
│  │ 1框 · 内容主舞台（常驻 · 可编辑）         │  │ 3列  │   4列        │  │
│  │ ┌─────────────────────────────────────┐ │  │ 模块 │ 参数 / 操作   │  │
│  │ │权项│说明书│附图│摘要│日志│历史 ←标签│ │  │📌标记│              │  │
│  │ ├─────────────────────────────────────┤ │  │🧹清洗│              │  │
│  │ │ 专利正文：内联图片 / 公式，          │ │  │🔣标点│   ……         │  │
│  │ │ 检查问题内联标黄 / 标红               │ │  │🔍孤立标│            │  │
│  │ │ （就地编辑，✓ 确认修改 回写内存）     │ │  │📝错别字│            │  │
│  │ └─────────────────────────────────────┘ │  └──────┴─────────────┘  │
│  ├─────────────────────────────────────────┤  ┌─────────────────────┐ │
│  │ 2框 · 当前子功能面板                      │  │ 📂 文件上传（跑马灯）│ │
│  │ （结果表 / 标记字典 / 参数卡片 /          │  │ 💾 文件生成          │ │
│  │   全文替换输入框 —— 随模块切换）          │  │ ☐ 打开目录    ⚙ 设置 │ │
│  └─────────────────────────────────────────┘  └─────────────────────┘ │
├──────────────────────────────────────────────────────────────────────┤
│ 状态栏：当前状态消息                                      [进度条]      │
└──────────────────────────────────────────────────────────────────────┘
  ↕ 三处可拖拽分隔条：1框↔2框、左区↔右区、3列↔4列；2框 可向下拖动收起
```

四个区域有固定简称，便于沟通定位：

- **1框** —— 左上**内容主舞台**（常驻）。六个标签页：`权利要求书 / 说明书 / 说明书附图 / 说明书摘要 /
  操作日志 / 操作历史`。专利正文在此查看、就地编辑、看内联图片 / 公式与高亮；约占左侧 2/3 高度，**不可收起**。
- **2框** —— 左下**当前子功能面板**，随右侧选中的模块切换（结果表 / 附图标记字典 / 参数卡片 /
  全文替换输入框）。可向下拖动收起。
- **3列** —— 右侧**第一列**，固定八个模块：`标记 / 清洗 / 标点 / 孤立标 / 错别字 / 重复字 / 权项 / 说明书`。
- **4列** —— 右侧**第二列**，随 3列 选择动态变化，放该模块的参数与操作按钮。

右侧列底部依次是：**文件上传按钮**（兼当前文件名提示，长名跑马灯滚动）、**💾 文件生成**、
一行「☐ 打开目录 + ⚙ 设置」。加载文档后八个模块同时就绪、互不影响，最后点「💾 文件生成」输出结果。

## 八大模块详解

> 交互通用规律：**3列 选模块 → 4列 点功能 → 2框 看结果 / 填参数 → 1框 看正文与高亮**。
>
> 凡是「参数在 2框、按钮在 4列」的功能，点执行按钮会**先把 2框 切回自己的参数页**，
> 保证你按下去的同时看得见「改的是哪里 / 按什么规则改」。

### 📌 标记

把「齿圈」在正文里变成「齿圈（1）」或「齿圈1」，同时保留所有格式。

- **2框** —— 「附图标记字典」编辑框：打开文档后自动扫描「附图说明」填入，识别不准可直接手改。
  编辑框下方两颗贴身按钮：`✅ 修改标记字典`（写回内存并记入操作历史）/ `🗑️ 清空标记字典`（只清编辑框）。
- **4列** —— 三组操作按钮：
  - *附图标记字典*：`🔄 重新提取标记`（从原始 docx 重抽）
  - *批量标注*：`⚡ 一键标注`（权项 + 具体实施方式）/ `📋 仅标注权利要求书` / `📝 仅标注具体实施方式`
  - *清除标记*：`🧹 删除所有标记`
- **只导入单独的说明书**（无权利要求书）时，用「仅标注具体实施方式」标注、「删除所有标记」清除即可。

### 🧹 清洗

- **4列** 两组：
  - *删除「所述」* —— `🗑️ 执行删除`；删除范围（章节）在 2框 勾选
  - *全文替换* —— `🔁 全文替换` 切到输入页填「替换前 / 替换后」（带实时预览），再点 `✅ 确认替换`；
    格式安全，保留公式 / 图片。「替换后」留空即为删除。

### 🔣 标点

- **4列** 两组：
  - *标点统一* —— `▶ 执行标点检查`：半角 ↔ 全角（顺序：半角→全角 → 全角→半角），**直接写入内存**。
    勾选项在 2框。仅在紧邻中文时替换，不影响英文 / 数字；不处理 `< >` 以免误伤数学符号；
    权利要求序号 `1.` `2.` 不会被替换成 `1。`。
  - *重复标点* —— `🔁 重复标点检查` / `✅ 应用所有修改`：**先看后改**，走 2框 共用结果表
- **重复标点检查**检出：同字符连写 `。。` `，，` `、、`、全角 / 半角混写 `，,` `。.`、逗号顿号混写 `，、`；
  英文省略号 `...` 与 `，。` 这类不同停顿的连写**不**误报，建议值统一取全角。
- 连续重复标点**不**再由「标点统一」顺手改掉 —— 统一交给「重复标点检查」逐条确认，避免闷头替换。

### 🔍 孤立标

- **4列** —— `🔍 检测孤立标记`（主操作）/ `🗑️ 清空结果`
- **2框** —— 说明 + 结果框。同时输出两类，**仅检测不修改**：
  - 孤立标记名：附图说明里有、具体实施方式里没有
  - 孤立图编号：附图说明提及「图 5」但正文未出现
- 标记字典为空时仍可检图编号，结果会注明标记名检查被跳过。

### 📝 错别字 / 🔁 重复字 / 🔣 重复标点

三类「先看后改」的检查，**共用 2框 同一张结果表**（标题随当前检查类型动态切换）。

- **4列** —— `忽略附图标记`（见「⚖️ 权项」末尾）/ `🔍 检查`（主操作）/ `✅ 应用所有修改`（把「修改后」列批量写回）/
  词库按钮（错别字词库 · 重复字忽略词库，均可增删 / 导入 / 导出）。
- **2框 结果表**五列：`章节 | 修改前 | 修改后 | 修改 | 忽略`
  - 「修改后」可直接编辑；点「修改」应用单条、点「忽略」跳过本条。
  - 同段同词出现多处时每处各占一行，「修改」**只改这一处**；其余行按改后的文本重新定位，
    可以忽略第 1 处、只改第 2 处。
- 错别字词库按子串匹配，收词时要避免跨词命中（如「限为」会命中「上限为」），这类条目宁可不收。
- **1框 内联高亮**：检查后所有问题在正文**标黄**；单击「修改前」跳转该处并**标红**。

### ⚖️ 权项

六项专业审查，配 1框 内联高亮 + 单击定位。

| # | 类型 | 检查目标 |
|---|---|---|
| ① | `antecedent` | **引用基础** —— `所述 X` 出现前，X 是否已在本权项或其引用的前序权项中定义 |
| ② | `dependency` | **引用关系** —— `根据权利要求 X 所述` 的 X 是否存在 / 前引 / 自引 |
| ③ | `vague` | **不确定用语** —— `约` / `大概` / `优选` / `左右` 等（内置 30 条词库，可编辑、可关） |
| ④ | `numbering` | **序号** —— 是否从 1 开始连续、有无重号、有无独立权利要求 |
| ⑤ | `multi_dep` | **多引合法性** —— 多项引用须用「或」、须写「中任一项」、不得多引多 |
| ⑥ | `ending` | **句号结尾** —— 每条权利要求必须以「。」结尾 |

**4列 参数**：`检查字数`（2~7 预设 + 自定义 2~30）/ `动态截断[黑名单]` / `动态回退` /
`不确定用语检查[词库]` / `忽略附图标记` / `▶ 开始检查`。点带下划线的功能名可看详细说明弹窗。

**引用基础降噪** —— 两个可叠加的开关：

- **动态截断**：从「所述」往后扫，遇到标点、单字虚词（的 / 与 / 在 / 为…）或边界黑名单词
  （安装 / 连接 / 包括…，内置 156 条可编辑）就停下，把累积的字当术语。
  黑名单词打头的常见部件名（`所述安装座` / `所述连接杆`）、序数前缀（`所述第一连接件`）都有专门保护。
- **动态回退**：取到术语后若匹配不上，就从右往左逐字缩短前缀重试，一直缩到 2 字仍不匹配才报错。

> 两个都勾选是**误判最低的组合**：先截断得到一个干净的最长术语，再对它做前缀回退。

**所有模式共用的判定规则**：

- `所述X` 与 `所述的X` 同等对待；`根据权利要求1、2或3中任一项所述` 这类引用语里的「所述」不算术语引用。
- **择一引用**（`权利要求1或2` / `1至3`）要求术语在**每条**被引分支里都有定义——只在权2 引入的特征，
  权3「根据权利要求1或2所述」再用「所述X」，会报「在引用权利要求 1 时缺少引用基础」。
- 序数前缀（`第一` / `第三`）不计入检查字数，回退也不会缩到只剩「第三」——`所述第三弹簧` 不会被别处的 `第三光路` 放过。
- 数量前缀（`多个` / `至少两个` / `若干` / `各`）匹配不上时剥掉再试：`包括若干连接杆…所述多个连接杆` 不误报。
- 同一个缺失术语在本权项及其从属权项里**只报首处**；单击「说明」直接跳到该处所在段落。

**2框 结果表**四列：`类型 | 权项 | 说明 | 操作` —— 可定位的问题已在 1框「权利要求书」标黄，
单击「说明」跳到 1框 并把该条标红；「操作」可忽略本条（本次会话有效，不写词库）。
在 1框 改完正文（记得「✓ 确认修改」）后再次「开始检查」即重扫。

> **前言保护**：权项首段开头的主题名称（`一种…` 到第一个逗号）不参与标注。

**忽略附图标记**（默认勾选；权项 / 错别字 / 重复字 / 标点四个模块各有一个开关，共用同一设置）——
先标注、再检查是常见流程。勾选后，权项六项检查以及错别字、重复字词、重复标点检查都在去掉附图标记的
文本上进行（括号编号 `齿圈（1）` / `连接件(3a)` / `侧板（11、12）`，以及标记字典里的无括号写法 `齿圈1`），
结果与标注前一致；不改文档，1框 的标黄与单击定位仍落在带标记的原文上（如「所述第二光源（1）发出」）。
否则标记会切断术语：「齿圈座」被标成「齿圈（1）座」后，`所述齿圈座` 会被当成 `所述齿圈` 检查而漏报。

### 📑 说明书

针对说明书 / 具体实施方式的只读检查，**共用 2框 结果表**，可逐步接入更多检查。

- **4列** —— `📑 实施例编号` / `📊 摘要字数`；按文档章节存在性自动启用。
- **实施例编号** —— 校验实施例标题应为 实施例一、实施例二、实施例三…**从「一」起、连续、
  不重复、不颠倒**。兼容 `实施例一` / `实施例1` / `第一实施例` / `实施方式一`（只看序号，不挑数字风格），
  并能区分标题与行内引用（「如实施例一所述」不计入）。
- **摘要字数** —— 「说明书摘要」文字部分超过 300 字时提示，并在 1框 标黄越界部分。
- **2框 结果表**四列：`类型 | 定位 | 说明 | 操作` —— 单击「说明」跳转 1框 标红
  （实施例 → 说明书标签，摘要 → 说明书摘要标签）。

## 公式与图片的内联显示

含附图 / 公式的标签页用富文本构建，**按段内文档顺序**插入文本与对象：

| 内容 | 来源 | 处理方式 |
|---|---|---|
| 附图 | PNG / JPEG | 直接解码显示，按 1框 宽度自适应缩放 |
| 公式（OLE） | MathType / AxMath / MS 公式编辑器 | 对象自带 WMF / EMF 预览位图，经 Windows GDI 转位图（`ui/render/formula.py`，纯 `ctypes` 零依赖） |
| 公式（OMML） | Word「插入 → 公式」 | **不带任何预览位图**，由 `ui/render/omml.py` 现场排版 |

### OMML 数学排版引擎

Word「插入 → 公式」写出的是 OMML XML，里面没有图片可用 —— 这正是这类公式以前只能显示成
【公式】占位的原因。V4.3.0 起，`ui/render/omml.py` 把 OMML 递归排成盒模型
（宽 / 基线上高 / 基线下深）再用 QPainter 绘制，零新依赖：

| 支持的结构 | OMML 元素 |
|---|---|
| 文本（变量斜体 / 运算符正体 + 两侧细空） | `m:r` `m:t` |
| 上标 / 下标 / 上下标 / 前置角标 | `m:sSup` `m:sSub` `m:sSubSup` `m:sPre` |
| 分式（横线 / 无线 / 线性） | `m:f` |
| 根式（含次数） | `m:rad` |
| 括号（随内容高度伸缩） | `m:d` |
| 大算符 ∑∏∫（上下限 / 角标两种摆法） | `m:nary` |
| 矩阵 | `m:m` `m:mr` |
| 函数名 / 上下限 / 重音 / 上下划线 / 边框 / 多行 | `m:func` `m:limLow` `m:limUpp` `m:acc` `m:bar` `m:borderBox` `m:eqArr` |

不认识的结构降级成「把里面的文字排成一行」，绝不留空白。字体优先 **Cambria Math**
（Word 公式默认字体，Windows 自带），依次回退 STIX / XITS / Times New Roman。

### 随主题取色

公式是现场排版成图片的，颜色烘焙在像素里，所以切换深 / 浅主题时会按新配色整体重排。
OLE 的 WMF 预览是「白底黑线」位图，深色主题下会变成正文里一排排白盒子 —— 现在把亮度反过来
当不透明度（白 → 透明、黑 → 不透明）再填成主题色，观感与 OMML 公式一致。
**只对灰阶图生效**：彩色附图抽样判定后原样保留。

> 每段仍是**一个段落 block、内联对象是块内占位符（U+FFFC）不增行**，因此「行＝段」的
> 编辑 / 回写 / 高亮模型完全不变。窗口缩放时按 1框 宽度防抖重排，图片走缓存不重复解码。

## 为什么不会破坏格式

所有自动化（标注 / 清洗 / 替换 / 错字回写）都**只修改 `<w:t>` 文本节点**，
完整跳过 `<w:drawing>`、`<m:oMath>`、`<w:object>` 等对象节点。三条核心约束：

1. **结构化编辑禁止增删段落** —— 保证段落索引稳定，否则定位 / 高亮会全盘错位。
2. **含对象段只读** —— 图片、OLE 公式、**OMML 公式**所在的段落不参与整段文本回写，
   避免占位符被当成正文写进 `w:t`。
3. **回写只认 `<w:t>`** —— 对象节点在替换前后逐字节保留。

## 典型工作流

**场景一：拿到初稿，做一轮全面自查**

1. 右键 docx →「用专利标记助手打开」（或直接拖入窗口）
2. **📝 错别字** → 检查 → 对着 1框 标黄逐条核对 → 应用所有修改
3. **🔁 重复字** → 检查 → 应用所有修改
4. **🔣 标点** → 执行标点检查 → 再跑重复标点检查，逐条确认后应用
5. **🔍 孤立标** → 检测孤立标记 → 看有没有图没被引用
6. **⚖️ 权项** → 勾上「动态截断 + 动态回退」→ 开始检查 → 单击「说明」跳 1框 逐条处理
7. **📑 说明书** → 实施例编号 / 摘要字数
8. **📌 标记** → `⚡ 一键标注`
9. `💾 文件生成` → 输出 `xxx_已标注.docx`

**场景二：先标注，再做引用基础等检查**

1. **📌 标记** → `⚡ 一键标注`
2. **⚖️ 权项** / **📝 错别字** / **🔁 重复字** / **🔣 标点**：保持「忽略附图标记」勾选（默认）→ 开始检查
3. 结果与标注前一致；单击结果照常跳到 1框 带标记的原文，修改也直接作用在原文上

**场景三：只想快速给具体实施方式加标注**

1. 拖入 docx
2. 在「📌 标记」模块核对 2框 的附图标记字典（改过就点 `✅ 修改标记字典`）
3. 4列 点 `📝 仅标注具体实施方式` → `💾 文件生成`

## 从源码运行

pip 方式 Python 3.10+ 即可运行：

```bash
pip install PyQt6 python-docx lxml
python main.py
```

或用 `uv`（按 `pyproject.toml` / `uv.lock` 锁定版本，Python 3.14；发版构建同一套版本）：

```bash
uv sync
uv run python main.py
```

命令行支持直接传入文件路径：`python main.py path/to/doc.docx`（启动后自动载入）。

跑回归测试（每个文件都能单独执行）：

```bash
python tests/test_smoke.py
python tests/test_claim_check.py
python tests/test_spec_check.py
python tests/test_punct_dup.py
python tests/test_omml.py
python tests/test_doc_ops.py
```

测试会打开主窗口，但通过 `tests/isolation.py` 改用临时设置与配置目录，不会改动你本机软件的勾选状态 / 窗口尺寸。

> **OLE 公式**的 WMF / EMF 预览依赖 Windows GDI（`gdi32` / `user32`），仅在 Windows 下可用，
> 其它平台回退为占位符。**OMML 公式**的排版是纯 Qt 实现，跨平台可用。其余功能不受平台影响。

## 常见问题

**Q：标注后公式 / 图形会消失吗？**
A：不会。所有自动化只动 `<w:t>` 节点，不碰 `<w:drawing>` / `<m:oMath>` / `<w:object>`。
如真遇到，请附最小复现文件反馈。

**Q：Word 里的公式在 1框 显示成【公式】？**
A：V4.3.0 起 Office Math（OMML）公式会被现场排版显示，不再是占位。若仍看到占位，
说明该公式用了尚未支持的结构 —— 此时会退化成公式里的纯文字，欢迎反馈样例。

**Q：1框 里某段改不动 / 是只读的？**
A：含图片、OLE 公式或 OMML 公式的段落为只读，避免占位符被当成正文写回。
纯文字段落可自由修改，改完点标签栏右上角「✓ 确认修改」回写内存。

**Q：为什么不能在 1框 里回车新增 / 删除整段？**
A：结构化编辑以「行＝段」维持段落索引稳定，禁止增删段落（否则定位 / 高亮会全盘错位）。
增删段落请回 Word 处理后重新导入。

**Q：深色主题下公式还是白底方块吗？**
A：V4.3.0 起不会了。白底黑线的公式预览会被转成透明底 + 主题色；彩色附图保持原样。

**Q：权项检查报了一堆「缺少引用基础」，怎么降噪？**
A：把「动态截断」和「动态回退」都勾上（误判最低的组合）。仍有误判时，把截不断的动词
加进「[黑名单]」词库即可 —— 词库越完善，识别越精准。

**Q：右键菜单「用专利标记助手打开」没有出现？**
A：安装时确认勾选了「文件关联」任务；或重新运行安装版选择「修复」；
或在 `HKCU\Software\Classes\SystemFileAssociations\.docx\shell\` 下确认 `专利标记助手` 键存在。

**Q：生成文件时提示「有未确认修改」？**
A：回 1框 点「✓ 确认修改」。这是防止 1框 手改的内容因忘记确认而遗失。

**Q：词库被删空了，怎么恢复？**
A：点编辑器里的「🔄 恢复内置」按钮，把内置词合并回当前列表。

**Q：单文件版首次启动特别慢？**
A：onefile 模式需要把内嵌文件解压到 `%TEMP%\_MEIxxx`，首启需 5–15 秒；之后稍快。
追求最快启动请用**安装版**（onedir，1–2 秒即启）。
